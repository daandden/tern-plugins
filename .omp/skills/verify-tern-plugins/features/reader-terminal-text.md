# Reader terminal text

When omp runs in a Tern pane, Tern shows its chat in the Reader style. This plugin gives omp's prose, composer, advisor notes, notices, and tool-result prose the terminal's font size, row height, and weight. Single-line chrome uses the terminal size and row height with Reader's own weights. Reader supplies the UI font from `settings.json`. The empty composer hides its placeholder text, the session title or "What are we cooking?", but keeps its height. Markdown horizontal rules use omp's theme colour.

## Sub-features

- `rtt-composer-size` gives the composer the terminal font size and row height.
- `rtt-composer-font` preserves Reader's `ui_font`-first font list and removes Reader's tight letter spacing.
- `rtt-placeholder` hides the placeholder of the empty composer and keeps the line. This rule applies to omp's composer in every chat style.
- `rtt-dock-gap` hides empty Reader dock regions, so their 24px top padding adds no blank rows above the composer.
- `rtt-chat-text` gives user messages, assistant prose, annotated assistant headings, and ask questions the terminal size and row height. Body text uses the terminal weight; bold text and headings use `bolder`. Sized headings keep Reader's font size. Horizontal rules keep the theme colour on a one-row block.
- `rtt-advisor-notices` gives advisor notes (`omp.advisor.note`), notice rows, and notice section bodies (`omp.notice.*`) the terminal size, weight, and row height. Notice section heads take the terminal size and row height with Reader's weight.
- `rtt-tool-prose` gives tool-result prose (`.sf-tool-body > .sf-md`) the terminal size, weight, and row height.
- `rtt-chrome` gives advisor heads and source labels, tool title, target, meta, time and more, card heads, chips, the working row, retry hint, and status line the terminal size and row height. Reader's own weights remain.

## How to get to it (user POV)

- Run `omp` in a Tern pane. The rules apply as soon as the composer shows.
- Send a prompt to see a user message and an assistant reply. Request headings, bold text, and a horizontal rule to check their formatting.
- Open Settings and search for **Chat style** to choose Reader, Spine, or Console and the Markdown heading style.

## Driving it with tern-verify

Preconditions:

- The baseline from `README.md`. Read `ui_font`, `font_size`, `adjust_cell_height`, and `font_weight` from `RUN/data/config/settings.json`; do not assume their values.
- The terminal row: before omp starts, run `"$V" ctl "$RUN" dump '.tn-pane.on .tv-grid' | jq -c '.elements[0] | {fontSize, lineHeight}'` in the shell pane. Its `lineHeight` is the row height `R` (also the grid's `--tv-lh`) and its `fontSize` the terminal size `S` (13px when `font_size` is null). Tern 0.9.16 has no `.tv-probe`.
- A helper for the composer: `ED=".sf-chat-reader .sf-col[data-role^='omp.editor']"`.

- Start omp. Run `"$V" type "$RUN" '/opt/homebrew/bin/omp --no-title'`, then poll `"$V" ctl "$RUN" tree "$ED" | jq .count` until it is 1. If the shell retained text at startup, press `key ctrl+c` before typing the command.
- Composer with the plugin. Run `"$V" ctl "$RUN" dump "$ED .sf-editor" | jq -c '.elements[0] | {rect, fontFamily, fontSize, fontWeight}'`. Its size is `S`, its height is `R`, and its weight matches `font_weight`. The font list starts with the copied `ui_font`. Dump `"$ED .sf-ed-ph"`; its `visible` value is `false`.
- Composer without the plugin. Drop both sheets in this window only: `"$V" ctl "$RUN" css plugin:local:reader-terminal-text:reader-terminal-text` and `"$V" ctl "$RUN" css plugin:local:reader-terminal-text:composer-placeholder`. Each prints `{"ok":true,"dropped":1}`. On Tern 0.9.16 the editor is `14px`, 22px high, and weight `400`. Its font list still starts with `ui_font`, followed by Reader's fallbacks, ending in `"Ioskeley Mono Term"`. The placeholder becomes visible.
- Restore with `"$V" tern "$RUN" plugin reload reader-terminal-text`. The dumps return to the plugin values. To check changed settings, run `"$V" ctl "$RUN" font 15` and `"$V" ctl "$RUN" adjust-cell-height 3`. Compare the composer height with a fresh `.tv-grid` dump. The 0.9.16 check gave 15px text and 22px rows for both. Restore the copied settings after this step.
- Chat text. Send `"$V" ctl "$RUN" type '"Reply with a Markdown h1, a paragraph with bold text and inline code, a horizontal rule, an h2, and a final short paragraph. Do not use code fences."'`, then `key enter`. Poll `tree ".sf-chat-reader [data-role^='omp.assistant'] > .sf-md"` until the answer appears. Dump that selector and `.sf-chat-reader .sf-card[data-role='omp.user'] .sf-md .md` before and after dropping the main sheet. With it, both use `S`, row height `R`, and the terminal weight. Without it, both use 14px and weight 400. Reader's assistant line height is 23.1px; the user line height is 21px.
- Bold and sized headings. Dump `.sf-chat-reader .sf-md .md strong` and `.sf-chat-reader .sf-md .md :is(h1,h2,h3,h4)`. At terminal weight 600, the plugin gives bold text and headings weight 900. Without it, the observed headings use 600. Automatic Reader headings keep 20px h1 and 17px h2 sizes with either sheet state.
- Annotated headings. Open `"$V" ctl "$RUN" prefs search '"chat style"'`. Find the row of the visible Markdown headings group (hidden settings groups come first, so on 0.9.16 it is `.pf-row:nth-child(7)`, not 5). Verify `tree '.pf .pf-row:nth-child(<n>) .pf-seg > button:nth-child(2)'` names **Annotated**, then click that selector with the quoting from `../SKILL.md`. Close settings with `prefs close`. Confirm `.sf-chat-reader.sf-h-annotated` exists. Repeat the heading dumps with and without the main sheet. With it, headings use `S` and `R`; without it, the observed headings use 14px and 21px rows. Restore **Automatic** with the first button of the same group.
- Ask questions. Ask the model to call the real `ask` tool with a short question and two options. Wait for `.sf-chat-reader .sf-md[data-role='omp.ask.question']`. Dump it with and without the main sheet. The plugin gives it `S` and the terminal weight. On the 0.9.7 check, the native question instead used 15px and weight 550. Cancel or answer the question before cleanup.
- Advisor notes and notices. Use an omp session with a real advisor note and notices, including a notice section with its body expanded. Dump `.sf-chat-reader [data-role='omp.advisor.note']`, `.sf-chat-reader .sf-row[data-role^='omp.notice.']`, and `.sf-chat-reader .sf-section[data-role^='omp.notice.'] > :is(.sf-section-head,.sf-section-body)`. Each visible match uses `S`; every match but the section head uses the terminal weight. In the developer console, read `line-height` for every matched element and confirm `R`. Compare the same nodes with the main sheet dropped, then reload `reader-terminal-text`.
- Tool-result prose. Ask the model to use a real tool that returns prose. Wait for `.sf-chat-reader .sf-tool-body > .sf-md`. Dump each visible match and read its computed `line-height` in the developer console. With the main sheet, the size is `S`, the weight is the terminal weight, and line-height is `R`. Drop the sheet to record Reader's values, then reload it.
- Single-line chrome. While the relevant cards and working state are visible, dump `.sf-chat-reader .sf-row[data-role='omp.advisor.head']`, `[data-role='omp.advisor.source']`, `.sf-tool-title`, `.sf-tool-target`, `.sf-tool-meta`, `.sf-tool-time`, `.sf-tool > .sf-tool-more`, `.sf-card-head :is(.sf-head,.sf-card-meta)`, `.sf-chip`, `.sf-row:is([data-role='omp.working'],[data-role='omp.hint.retry'])`, `[data-role='omp.working'] :is(.sf-shimmer,[data-role='omp.working.label'])`, and `.sf-status[data-role='omp.status'], .sf-status[data-role='omp.status'] .sf-seg-t`. Scope every selector to `.sf-chat-reader`. Each visible match has size `S` and computed line-height `R`. Record weights before and after dropping the main sheet: they stay at Reader's values, not the terminal weight. Reload the plugin after the comparison.
- Horizontal rule. Dump `.sf-chat-reader .sf-md .md hr` and inspect its `background-image` in the developer console. Compare it with the same element's `--omp-mdHr`, using the console commands in `../SKILL.md`. It must use that colour, not `--l2`. The 0.9.7 dark Catppuccin check gave `linear-gradient(#7e8095, #7e8095)`. The old rule instead gave `linear-gradient(rgb(205 214 244 / 0.09), rgb(205 214 244 / 0.09))`.
- Placeholder in other chat styles. Search settings for **Chat style** again. The first `.pf .pf-seg` group contains Reader, Spine, and Console in that order. Select Spine, then Console, and dump each style's `.sf-ed-ph` before and after dropping only `composer-placeholder`. It changes from hidden to visible with identical geometry. Reload the plugin and restore Reader.
- Empty dock regions. A fresh omp has one Reader dock region; panes that have run for a while can hold empty ones. Count them with `"$V" ctl "$RUN" dump '.tn-pane.on .tv-dock .sf-region.sf-chat-reader' | jq -c '[.elements[] | {h: .rect[3], visible}]'` and list each region's children with `... .sf-region.sf-chat-reader *`. With the `dock-gap` sheet, a region whose children are all `.sf-void` has height 0 and is not visible. Drop only `plugin:local:reader-terminal-text:dock-gap`: each such region becomes 24px high and the composer moves down by 24px per region. Reload the plugin. If the run has no empty region, record the check as skipped.
- Proof. Save each dump as `RUN/rtt-<step>.json` and take `"$V" shot "$RUN" rtt-<step>` before and after each sheet drop. Read the WebP shots. For `line-height`, `letter-spacing`, and `background-image`, keep the developer console's `.dc-row` output as well.

## Gotchas

- The prompt step sends a real request to the model that your omp configuration names, and it costs tokens. Ask the user before you run it. The composer steps send nothing.
- `omp` in the zsh pane is the first one on its `PATH` (`whence omp`), `~/.bun/bin/omp` at the last check, not the omp that Tern manages under `~/.config/tern/omp/bin`. Name the path in `notes.md`.
- Dropping a sheet with `ctl css NAME` changes this window only, until the next plugin reload. It does not prove that a rule matches when the file changes. To test an edit to `window.luau`, run `"$V" tern "$RUN" plugin reload` and dump again.
- The rules match Tern's class names and omp's `data-role` values (`.sf-chat-reader`, `omp.editor`, `omp.assistant`, `omp.user`, `omp.advisor.*`, `omp.notice.*`, and the tool and chrome selectors above). A missing node is not proof that its rule works. Report renamed selectors or unavailable fixture states separately.
- `stop` removes the omp session dir of `RUN/data`. omp in another dir leaves a session dir that `stop` does not know.
- Tern 0.9.7 already uses the UI font in Reader's composer. Expect the same first family with and without the plugin, not Geist first without it.
- The 0.9.7 engine accepts a stylesheet containing `font-weight: min(900, calc(var(--tv-weight) + 300))` without reporting a parse error, but does not apply the weight. A live weight-500 check gave 500 with that expression, 700 with `bolder`, and 800 with a numeric control. Keep the `bolder` comparison.
- Advisor notes, notice rows, notice sections, tool prose, and individual chrome parts need visible nodes of their own. If the session cannot produce one, record that check as skipped with its missing precondition. Never substitute assistant prose or insert fake nodes.
