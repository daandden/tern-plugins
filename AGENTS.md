# Tern plugins

This repo holds custom Tern plugins. Each top-level folder other than `bin/` and `docs/` is one plugin, with a `plugin.toml` manifest and a `window.luau` script. The folder name is the `id` in `plugin.toml`. `bin/` holds shell commands that work with the plugins.

## Loading

Tern loads each plugin from its folder in this repo. `tern plugin link <folder>` wrote a `<id>.path` file into the plugins directory (`tern plugin dir`, `~/.config/tern/plugins`), and that file names the folder. An edit here is the live plugin after a reload.

After each change:

1. Run `tern plugin reload`. It exits 1 when a plugin fails to load.
2. Run `tern plugin list` and make sure that each plugin shows `ready`.

To add a plugin, create `<id>/plugin.toml` and `<id>/window.luau`, then run `tern plugin link` once with the absolute path of the folder.

## Luau API

`tern plugin types <folder>` writes `<folder>/tern.d.luau`, the type definitions for luau-lsp. Read it for the API that the plugins use (`tern.command`, `tern.css`, `tern.route`, `cx.layout`, `cx.session`). The file comes from the installed Tern version, so `.gitignore` keeps it out of the repo. The SDK and its example plugins are at https://github.com/stencil-hq/tern-sdk.

## Conventions

Indent Luau with tabs. Each `window.luau` starts with a comment that says what the plugin does, and each function or command has a comment above it that says what it does. In zellij-keys, that comment names the Zellij action that the command copies.

## Plugin notes

zellij-keys: `~/.config/tern/settings.json` binds its commands as `plugin.zellij-keys.<command id>`. If you rename a command id, change its keybind in `settings.json` too. The float commands use absolute paths in `/opt/homebrew/bin`, because Tern runs them through the login shell and that `PATH` does not include `/opt/homebrew/bin`.

zellij-keys floats: the `float-size` sheet puts a focused float (`.tn-pane.pip.pip-focus`) in the middle 75% of the tab. Tern writes the float's position and size inline, so the rule needs `!important`, and Tern's engine ignores `inline-size`, so it uses `width` and `height`. Tern animates floats outside CSS, so a command that changes a float first calls `quiet_float_motion`, which sets `reduce_motion` to `on` for 400 ms. The user's value waits in `tern.kv` under `reduce_motion_before_float`, and `window_start` restores it if Tern stopped in between. Floats that the mouse focuses or unfocuses still animate.

`keybinds.html` is the guide to every key that `~/.config/tern/settings.json` binds, grouped by zellij mode. When you add, remove or change a keybind or a zellij-keys command, change its row in the guide and the key count at the top.

reader-terminal-text: the plugin is CSS only, through `tern.css`. Its selectors use the class names and `data-role` values of Tern's Reader chat style (`.sf-chat-reader`, `omp.assistant`, `omp.editor`). If a Tern update changes these names, the rules stop working. The `:root` and `:root:root` prefixes give each rule a higher specificity than the Reader rule it replaces.

html-links: every local HTML file opens as the rendered page, never as source. `tern.route.link` handles `file://` URLs to HTML files, and `tern.route.open` handles HTML files from every origin: clicked plain paths, the Files pane, the palette, `tern open`, `bin/open` and macOS open (Tern is the default app for HTML). A plain path does not go through the link route. When the rule for HTML files changes, change both handlers and `is_html` in nvim-files. The link route returns nil for other `file://` URLs, so nvim-files gets them. A page docks beside its opener pane. When that pane is a float (Yazi runs as one), `tiled_pane` finds the tiled pane under it in `cx.session:layout(tab).floats`, because a page docked beside a float stays a float. nvim-files keeps the same `tiled_pane`.

html-links Cmd+R: `reload_page` reloads the focused browser pane, or from another pane the `file://` pages in its tab. Tern drops a plugin default key that a preset binds, and the preset binds `cmd+r` to SQLite actions. So `settings.json` binds `cmd+r` to a list: the four SQLite actions first, then `plugin.html-links.reload_page`. In a SQLite block, the SQLite action runs. If a Tern update changes the preset for `cmd+r`, change the list too.

nvim-files: local text files open in `/opt/homebrew/bin/nvim` in a terminal pane, because Tern's code view has no line height setting (https://github.com/stencil-hq/tern-sdk/issues/20). Markdown, notebooks, images, PDFs, databases, binary files, symlinks and files over 4 MiB stay in Tern. The plugin needs both routes. `tern.route.open` covers the Files pane, the palette, `tern open`, `bin/open` and clicked plain paths. `tern.route.link` covers clicked `file://` URLs: a link route that answers `{ path = ... }` makes Tern open its own file block without calling `route.open`. Tern asks html-links' link route before this one, so html-links returns nil for the URL of a file that is not HTML. A `file://` URL that does not go to Neovim gets `{ path = ... }` here and opens in Tern's file block. The plugin keeps the ids of its Neovim panes in `tern.kv` under `panes`, because a reload of any plugin resets every plugin's Lua state. A second file in the same tab goes to that pane as a typed `:drop` command (`cx:run`, not `cx.session:run`). A new Neovim pane from a float opener splits the tiled pane under the float (`tiled_pane`). Both routes return nil for every HTML file, so html-links handles it. If the HTML rule of html-links changes, change it here too. When the issue is fixed, remove the plugin, and make the link route of html-links return `{ path = path }` again for the URL of a file that is not HTML.

bin/open: `~/.local/bin/open` is a symlink to `bin/open`, and `~/.local/bin` comes before `/usr/bin` in `PATH`. In a Tern pane (`TERN_PANE` is set), `open FILE...` with only local files runs `tern open` for each file, so the file opens beside that pane in its tab, also when you look at another tab. macOS open names no pane, so Tern opened such a file beside the focused pane. Every other call goes to `/usr/bin/open`. Tern does not give the pane of `tern open` to a plugin route, so the script writes the real path of the file to `~/.cache/tern/open-owners/<pane>.<pid>` first. html-links and nvim-files read the pane from that file in `take_opener` and remove the file. When two panes open the same path at once, `take_opener` takes the file of the focused pane, because `tern open` focuses the pane that runs it before the route runs. `tern open` exits 1 with "cannot open in a file block" when a plugin opened the file, so the script treats a removed handoff file as success and hides that message. `tern open` also shows the pane's tab, so the window moves to the tab of the pane that ran `open`. Both plugins keep the same `take_opener`. If you change it, change both.

Yazi: `~/.config/yazi/yazi.toml` (outside this repo) sends `*.{html,htm}` to the openers `open` and `edit`. Enter runs Yazi's `open` opener (`open %s`). The login shell is fish, and fish finds `bin/open` there, so the rendered page opens beside the tiled pane under the Yazi float. The "open with" menu (`O`) also offers `$EDITOR`. Without the rule, Yazi's preset sends `text/html` to the editor. In zsh and bash login shells, `/usr/bin` comes before `~/.local/bin`, so those shells miss `bin/open`.

goto: the window half lists sessions, tabs and tiled panes and passes them as JSON in the launch argument of the `goto.picker` block (host half). A tab with one pane is one row with that pane's status; only a split tab gets pane rows under it. A row is marked `agent` when its pane is in `cx.agents:list()` (a split tab when one of its panes is), and a split tab with exactly one agent pane names that pane's row in `solo`. After the tree rows, `collect` adds the Waiting on you rows (`group = true`): a copy of each row whose status is in `ATTENTION` (needs input, error, alert, done, idle), except the row you are in, by status and then tree order. The host half filters the rows: it opens with agents only (`in_view`: every session row, the tabs and panes marked `agent`, and a `solo` tab as one row that shows and goes to its agent pane through `target`), and `a` in move mode switches to all panes and back. `in_view` also hides the idle Waiting on you rows until `i` in move mode shows them. Tern has no plugin settings: `plugin.toml` rejects unknown keys, `cx.settings` knows only Tern's own preferences, and Tern drops an unknown key from `settings.json` when it writes the file. So `i` stores its choice in `tern.kv` under `waiting_idle` (default hidden), and each picker reads it in `init`. It shows the Waiting on you rows first, named session / tab / pane, then a thin line (an extra list item with the role `goto.sep`, outside the rows, so the cursor, jump numbers and clicks skip it), then the tree. It hides the group during a search, and `place_cursor` starts the cursor on the first group row, else on your pane's row, its `solo` tab row, or your session's row. In search mode a typed digit is a jump number, as in move mode, so a search holds no digits. The footer shows the search on the left and is empty there without one. The block reports the row you pick as a `goto:session/<id>`, `goto:tab/<id>`, `goto:pane/<id>` or `goto:close` link, and the window's `tern.route.link` makes the move. Pane status starts from `cx.agents:list()`: Tern lists omp panes there as agents (state `working`, `waiting_input`, `idle` or `exited`) even though they run in a terminal, and `cx.session:panes()` gives `busy` and `alert` for plain terminals. Tern's four states hide most of omp's state, so `omp_signals` also reads the `dock` and `layer` regions of the agent's surface (`cx.session:surface` with `root`; never the `main` region, which holds the whole chat) and looks for omp's roles: `omp.ask.question` or `omp.plan.options` (it waits for you, while Tern still says `working`), `omp.working` with a `meter` child (retry countdown) or a `progress` child (compaction), `omp.errorBanner` (a pinned error) and `omp.hud.pill` (subagents or background jobs running while the agent is idle). These role names come from omp's TSP UI, not from an API, so an omp update that renames them turns those statuses back into Tern's plain ones. The rows are a Tern `ui.list`, because only a list keeps the cursor row in view; its id is `main.box.rows` because it sits in the box element keyed `box`. List item nodes drop child elements, so a row is styled spans only, all in the item's label: the jump number, the status mark, then the tree as box-drawing characters and the name. The jump number is plain `muted` text, and a typed first digit is `accent strong`. Every mark fills one 22 px slot so the names line up: a still glyph, or the empty slot of a row with no status, carries the `icon` token (Tern adds a margin after an icon span, which the sheet sets to 0), and the moving marks get margins that add up to 22 px. A still glyph uses the font `Symbols Nerd Font`: the `icon` token's font (Berkeley Mono, not installed) falls back to a font that draws the glyph past the right edge of its width, 2 px right of the slot's center. Without `Symbols Nerd Font`, the glyphs move off center again. An item and the list keep a `role` prop, which Tern writes as `data-role`, and that is the CSS hook of the line and of `goto.flat`. A status shows as a mark with no word. Plugin spans keep only Tern's own style tokens (custom tokens are dropped), so the CSS hooks onto Tern tokens: a moving mark is a no-break space with `num` plus a second token that picks it (`accent` working: Tern's step marker arc with `tnHdSpin`; `em` busy terminal: orbit dot with `sf-turn`; `ins` compacting: sliding bar with `sf-indet`; `del` three times, subagents or jobs: dots with `sf-dot`; `mark` retrying: widening rings in `--warn` with `tnRing`; `muted` idle: still hollow ring). A status that waits for you is a still Nerd Font glyph. A block region can carry `sf-still`, which stops animations, so each animation needs `!important`; the mark rules must not require `sf-still`, because a region does not always have it, and then the mark does not draw at all. The box and footer use the class names of Tern's command palette (`cmdk`, `ck-foot`, `kbd`), so Tern's own palette CSS styles them. If a Tern update renames those classes, tokens or keyframes, the picker loses that look. The `palette` sheet in `window.luau` fixes the floating pane to the window at the palette's spot (`12vh` from the top, centered with `50vw`), so an open file tree does not shift it. Its height of 511 px fits 20 rows of 22 px, the 13 px line, the list padding (12 px at the top, to match the space under the footer text, and 6 px at the bottom) and the 40 px footer, which must not shrink (`flex: none`); change it with the row height. A list with no line (no Waiting on you rows, or a search) has the role `goto.flat` and takes the line's 13 px as bottom padding, outside the scrolling area, so no part of a 21st row shows. It matches the pane by its accessible name (`aria-label` that starts with `Go to,`), because Tern's CSS engine has no `:has()`. The pane's shadow stops at the pane area, so while a picker is open the `veil` sheet darkens the rest of the window like the palette's veil: an inset shadow on `body` for the window background, and `filter: brightness(0.45)` on the tab bar items and the file tree. Keep the terminal grid of the pane in the page (the sheet only makes it invisible): it holds the input that sends typed keys to the block. `window_start` does not run after `tern plugin reload`, so a timer that starts when `window.luau` loads closes picker panes left from before the reload. `GLOSSARY.md` names the terms, and `docs/adr/0001-goto-picker-as-floating-block.md` gives the reason for the float.

## vstack

### Issue tracker

Issues live in the GitHub Issues of `daandden/tern-plugins`, and the skills use the `gh` CLI. See `docs/vstack/issue-tracker.md`.

### Triage labels

The repo uses the five default triage labels, and each label is the same as its role name: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human` and `wontfix`. See `docs/vstack/triage-labels.md`.

### Domain docs

The repo is single-context: one `GLOSSARY.md` at the repo root and the ADRs in `docs/adr/`. See `docs/vstack/domain.md`.
