# Tern plugins

This repo holds custom Tern plugins. Each top-level folder other than `bin/` and `docs/` is one plugin, with a `plugin.toml` manifest and a `window.luau` script. The folder name is the `id` in `plugin.toml`. `bin/` holds shell commands that work with the plugins.

## Loading

Tern loads each plugin from its folder in this repo. `tern plugin link <folder>` wrote a `<id>.path` file into the plugins directory (`tern plugin dir`, `~/.config/tern/plugins`), and that file names the folder. An edit here is the live plugin after a reload.

After each change:

1. Run `tern plugin reload`. It exits 1 when a plugin fails to load.
2. Run `tern plugin list` and make sure that each plugin shows `ready`.

To add a plugin, create `<id>/plugin.toml` and `<id>/window.luau`, then run `tern plugin link` once with the absolute path of the folder.

## Luau API

`tern plugin types <folder>` writes `<folder>/tern.d.luau`, the type definitions for luau-lsp. Read it for the API that the plugins use (`tern.command`, `tern.css`, `tern.route`, `cx.layout`, `cx.session`). The file comes from the installed Tern version, so `.gitignore` keeps it out of the repo. The SDK and its example plugins are at https://github.com/stencil-hq/tern-sdk.

## Conventions

Indent Luau with tabs. Each `window.luau` starts with a comment that says what the plugin does, and each function or command has a comment above it that says what it does. In zellij-keys, that comment names the Zellij action that the command copies.

## Plugin notes

zellij-keys: `~/.config/tern/settings.json` binds its commands as `plugin.zellij-keys.<command id>`. If you rename a command id, change its keybind in `settings.json` too. The float commands use absolute paths in `/opt/homebrew/bin`, because Tern runs them through the login shell and that `PATH` does not include `/opt/homebrew/bin`.

zellij-keys floats: the floating panes of a tab are shown or hidden together, as in Zellij. The `focus` handler hides the shown floats of a tab with Tern's `pip_stash_all` when focus goes to a tiled pane of that tab from a pane of the same tab (a click, a key or an open). A focus that comes from another tab or session hides nothing, also when it lands on a tiled pane of a tab whose floats are shown. `focus_tab` keeps the tab of the last focus for that test. Alt+F from a tiled pane shows the floats and focuses the last used floating pane of the tab. A new float (`open_float`, `toggle_float`) shows the hidden floats first. `pip_stash_all` toggles the floats of the active tab, and Tern does not tell a plugin whether a float is hidden. So `tern.kv` keeps the tabs with shown floats under `shown_floats`, and an override of `pip_stash_all` flips that state when Tern's own key or palette entry runs it. A call from `cx:command` skips the override. `tern.kv` keeps the last used floating pane of each tab under `last_float`, because a reload of any plugin resets every plugin's Lua state.

zellij-keys close: when the focused float closes and other floats of the tab are shown, `pane_closed` focuses the last used float of the tab, else the float before it in open order, else the one after it. `pane_closed` comes before the `focus` event of Tern's own move to the tiled pane, and the `focus` handler skips an event whose pane no longer has focus. The Go to picker counts as a focused float there, so Esc in a picker that a float opened goes back to that float. goto closes the picker before it focuses the target of a jump, and Tern first moves focus to the tiled pane under the picker. So a jump to that tiled pane gives the same events as Esc and also goes back to the float. Only a jump to another pane hides the floats. The picker is a `goto.picker` block, and `is_picker` leaves it out of the floating panes.

zellij-keys cascade: the `float-size` sheet draws each shown floating pane at half the tab (`.tn-stage`) in width and in height. The first float is centered, and each later one sits 16 px to the right and 32 px lower, in open order. After 8 places, the cascade starts at the top again and keeps going right, for 16 places. The sheet depends on Tern's class names: each float is a `section.tn-pane.pip` child of `.tn-stage` in open order, whatever its corner, a stashed float has `off`, a float that Tern does not draw has `off` and `pip-hidden`, the focused float has `pip-focus`, the floats behind it have `pip-glance` and `pip-peek` with a tilt transform, and `.tn-pip-chip` is the "Show all" chip. The stage also keeps the panes of each other tab that you looked at, with `off`. If a Tern update renames them, the cascade stops working. `:nth-child(k of .pip:not([aria-label^="Go to,"]):not(.off))` counts the drawn floats of the tab you look at without the Go to picker, so the picker keeps the box of goto's `palette` sheet and does not move the cascade. Tern writes the position, size and transform of a float inline, so each rule needs `!important`. Tern's engine ignores `inline-size`, so the rules use `width` and `height`. Tern paints the focused float on top with no `z-index`. The rules replace Tern's inline position, so the mouse cannot drag or resize a shown float. Issue #3 (https://github.com/daandden/tern-plugins/issues/3) waits for Tern to make that possible.

zellij-keys moves: Ctrl+G M and Ctrl+G R move and resize the focused float by a tenth of the tab, and Ctrl+G R +, Ctrl+G R -, Alt + and Alt - grow or shrink it on all sides, half a step on each side. A float that you moved or resized keeps its own spot until it closes or docks: through hide and show, a tab switch and a plugin reload. `tern.kv` keeps the spots under `float_spots`, by pane id, as parts of the tab (`x`, `y`, `w`, `h`), so a spot scales with the tab. `settle` keeps the float inside the tab and at least a fifth of it. An edge that ends within 5% of a tab edge snaps to 10 px from that edge when the change moved it toward that tab edge, or when it was snapped and did not move away. So a shrink of a float that fills the tab lets go of the edges, and a move to the side leaves the top and bottom as they were. The resize commands clamp the size before they move the float, so at a fifth of the tab or the full tab a grow or shrink changes nothing, and Ctrl+G R with L or J stops at the tab edge with the top-left corner in place. The flags `l`, `r`, `t` and `b` mark the snapped edges, and the rule of a snapped edge uses px, so the gap stays 10 px at each tab size. `render_spots` writes the `float-spots` sheet: one rule per moved float of the tab you look at, with the same `:nth-child` count as the cascade and one more `:root`. It runs on each focus, close and change, because the count changes with the tab and with each float that opens or closes. A moved float keeps its place in the count, so the cascade place it left stays empty. A plugin cannot read the size of the tab, so the first move starts from the cascade place with its px offsets turned into parts of a 1260 by 710 tab (`TAB_GUESS`). Overrides of `move_pane:*` and `equalize` handle a float and return false for a tiled pane, so Tern's own action runs. Tern's `resize_split:*` is a key action that a plugin cannot override, so `settings.json` binds Ctrl+G R with H, J, K, L and the arrows to the `resize_*` commands, which run `resize_split:*` through `cx:action` for a tiled pane. Tern spells the keys as `ctrl+g>r>shift+=` (+), `ctrl+g>r>-`, `alt+shift+=` (Alt +), `alt+=` and `alt+-`.

zellij-keys corners: Tern draws at most 4 floats in one corner stack (the floats of one tiled pane in one corner), and it gives the oldest floats of a fuller stack `off` and `pip-hidden`, also the focused one. Tern draws the whole stack only while the pointer is over it (a fanned deck, `pip fan` in `tern ctl`), and only one stack at a time: a fan of another stack folds the first one again. No action in Tern's action list fans a stack, so a plugin cannot keep one fanned. So `place_floats` puts the floats of each tiled pane in the corners `br`, `bl`, `tr` and `tl`, oldest first, with room for 3, 4, 4 and 4. `br` comes first, so up to 3 floats still hide to the right, and it keeps one place for the Go to picker, which goto opens there. So Tern draws 15 floats per tiled pane. With more, `br` takes the extra ones, and Tern draws 16, or 15 while the picker is open, and hides the oldest ones of `br`. A focused float never goes to a hidden place. `note_float_focus` calls `place_floats`, so each float focus places the floats again. The cascade rules set the position of a shown float, so its corner does not show.

zellij-keys motion: Tern animates floats outside CSS, so a command or handler that changes a float first calls `quiet_float_motion`, which sets `reduce_motion` to `on` for 400 ms. The user's value waits in `tern.kv` under `reduce_motion_before_float`, and `window_start` restores it if Tern stopped in between. Floats that the mouse focuses or unfocuses still animate. While `reduce_motion` is `on` and the window gets no input, `tern.timer` and `tern.sleep` do not fire, so the value stayed `on` until the next key. The 400 ms wait is a `/bin/sleep 0.4` process through `tern.process.run`, whose callback comes on time, and only the wait of the last call restores the value.

zellij-keys agent tab: Alt+Shift+T (`new_agent_tab`) opens a new tab with an agent block, in the folder of the focused pane. Tern has no action for an agent tab, and `cx.agents:start` rejects a blank prompt. So the command sets the setting `new_blocks` to `Agent` (the enum spelling, with a capital letter), runs `new_tab` and sets the user's value again. Tern writes `settings.json` for each change of `new_blocks`.

`keybinds.html` is the guide to every key that `~/.config/tern/settings.json` binds, grouped by zellij mode. When you add, remove or change a keybind or a zellij-keys command, change its row in the guide and the key count at the top.

reader-terminal-text: the plugin is CSS only, through `tern.css`. Its selectors use the class names and `data-role` values of Tern's Reader chat style (`.sf-chat-reader`, `omp.assistant`, `omp.editor`). If a Tern update changes these names, the rules stop working. The `:root` and `:root:root` prefixes give each rule a higher specificity than the Reader rule it replaces.

html-links: every local HTML file opens as the rendered page, never as source. `tern.route.link` handles `file://` URLs to HTML files, and `tern.route.open` handles HTML files from every origin: clicked plain paths, the Files pane, the palette, `tern open`, `bin/open` and macOS open that names Tern (`open -a Tern`). A plain path does not go through the link route. When the rule for HTML files changes, change both handlers and `is_html` in nvim-files. The link route returns nil for other `file://` URLs, so nvim-files gets them. A page docks beside its opener pane. When that pane is a float (Yazi runs as one), `tiled_pane` finds the tiled pane under it in `cx.session:layout(tab).floats`, because a page docked beside a float stays a float. nvim-files keeps the same `tiled_pane`.

html-links web links: the link route returns nil for a URL to this machine (`localhost`, `*.localhost`, `127.x.x.x`, `::1`, `0.0.0.0`, or the local host name from `cx.hosts:list()`, also with `.local`), so Tern opens it. Every other web URL goes to `/usr/bin/open -a "Microsoft Edge"`. A link that you click inside a Tern page does not go through the route, so it stays in that page.

Default browser: Microsoft Edge is the macOS default app for `http`, `https` and HTML files. macOS keeps the three together: when Tern becomes the app for HTML files, it also becomes the default browser. So a URL or an HTML file that another app opens (Finder, Slack, `/usr/bin/open`) goes to Edge, and only opens that go through Tern reach the plugin routes.

html-links Cmd+R: `reload_page` reloads the focused browser pane, or from another pane the `file://` pages in its tab. Tern drops a plugin default key that a preset binds, and the preset binds `cmd+r` to SQLite actions. So `settings.json` binds `cmd+r` to a list: the four SQLite actions first, then `plugin.html-links.reload_page`. In a SQLite block, the SQLite action runs. If a Tern update changes the preset for `cmd+r`, change the list too.

nvim-files: local text files open in `/opt/homebrew/bin/nvim` in a terminal pane, because Tern's code view has no line height setting (https://github.com/stencil-hq/tern-sdk/issues/20). Markdown, notebooks, images, PDFs, databases, binary files, symlinks and files over 4 MiB stay in Tern. The plugin needs both routes. `tern.route.open` covers the Files pane, the palette, `tern open`, `bin/open` and clicked plain paths. `tern.route.link` covers clicked `file://` URLs: a link route that answers `{ path = ... }` makes Tern open its own file block without calling `route.open`. Tern asks html-links' link route before this one, so html-links returns nil for the URL of a file that is not HTML. A `file://` URL that does not go to Neovim gets `{ path = ... }` here and opens in Tern's file block. The plugin keeps the ids of its Neovim panes in `tern.kv` under `panes`, because a reload of any plugin resets every plugin's Lua state. A second file in the same tab goes to that pane as a typed `:drop` command (`cx:run`, not `cx.session:run`). A new Neovim pane from a float opener splits the tiled pane under the float (`tiled_pane`). Both routes return nil for every HTML file, so html-links handles it. If the HTML rule of html-links changes, change it here too. When the issue is fixed, remove the plugin, and make the link route of html-links return `{ path = path }` again for the URL of a file that is not HTML.

bin/open: `~/.local/bin/open` is a symlink to `bin/open`, and `~/.local/bin` comes before `/usr/bin` in `PATH`. In a Tern pane (`TERN_PANE` is set), `open FILE...` with only local files runs `tern open` for each file, so the file opens beside that pane in its tab, also when you look at another tab. macOS open names no pane, so Tern opened such a file beside the focused pane. Every other call goes to `/usr/bin/open`. Tern does not give the pane of `tern open` to a plugin route, so the script writes the real path of the file to `~/.cache/tern/open-owners/<pane>.<pid>` first. html-links and nvim-files read the pane from that file in `take_opener` and remove the file. When two panes open the same path at once, `take_opener` takes the file of the focused pane, because `tern open` focuses the pane that runs it before the route runs. `tern open` exits 1 with "cannot open in a file block" when a plugin opened the file, so the script treats a removed handoff file as success and hides that message. `tern open` also shows the pane's tab, so the window moves to the tab of the pane that ran `open`. Both plugins keep the same `take_opener`. If you change it, change both.

Yazi: `~/.config/yazi/yazi.toml` (outside this repo) sends `*.{html,htm}` to the openers `open` and `edit`. Enter runs Yazi's `open` opener (`open %s`). The login shell is fish, and fish finds `bin/open` there, so the rendered page opens beside the tiled pane under the Yazi float. The "open with" menu (`O`) also offers `$EDITOR`. Without the rule, Yazi's preset sends `text/html` to the editor. In zsh and bash login shells, `/usr/bin` comes before `~/.local/bin`, so those shells miss `bin/open`.

goto: the window half lists sessions, tabs and tiled panes and passes them as JSON in the launch argument of the `goto.picker` block (host half). A tab with one pane is one row with that pane's status; only a split tab gets pane rows under it. A row is marked `agent` when its pane is in `cx.agents:list()` (a split tab when one of its panes is), and a split tab with exactly one agent pane names that pane's row in `solo`. After the tree rows, `collect` adds the Waiting on you rows (`group = true`): a copy of each row whose status is in `ATTENTION` (needs input, error, alert, done, idle), except the row you are in, by status and then tree order. The picker has one mode: a typed letter or space goes into the search at once, a digit is a jump number (so a search holds no digits), only Up/Down move, and Esc clears the first digit, then the search, then closes. The actions sit behind the prefix `ctrl+;` (`state.prefix`): then `a` switches agents only and all panes, `i` shows or hides idle agents in Waiting on you, and every other key only ends the prefix. Tern's keymap does not bind `ctrl+;`, and the block gets it as `ctrl` with the name `;`; if `settings.json` ever binds `ctrl+;`, the prefix stops working. The host half filters the rows: it opens with agents only (`in_view`: every session row, the tabs and panes marked `agent`, and a `solo` tab as one row that shows and goes to its agent pane through `target`). `in_view` also hides the idle Waiting on you rows until `i` shows them. Tern has no plugin settings: `plugin.toml` rejects unknown keys, `cx.settings` knows only Tern's own preferences, and Tern drops an unknown key from `settings.json` when it writes the file. So `i` stores its choice in `tern.kv` under `waiting_idle` (default hidden), and each picker reads it in `init`. It shows the Waiting on you rows first, named session / tab / pane, then a thin line (an extra list item with the role `goto.sep`, outside the rows, so the cursor, jump numbers and clicks skip it), then the tree. It hides the group during a search, and `place_cursor` starts the cursor on the first group row, else on your pane's row, its `solo` tab row, or your session's row; `set_query` puts it there again when the search becomes empty. The footer shows the search and a text cursor on the left and is empty there without one; its keys are `↑ ↓ move`, `↵ go` and `⌃; actions`, and while the prefix waits, the two actions and `esc cancel`. The block reports the row you pick as a `goto:session/<id>`, `goto:tab/<id>`, `goto:pane/<id>` or `goto:close` link, and the window's `tern.route.link` makes the move. Pane status starts from `cx.agents:list()`: Tern lists omp panes there as agents (state `working`, `waiting_input`, `idle` or `exited`) even though they run in a terminal, and `cx.session:panes()` gives `busy` and `alert` for plain terminals. Tern's four states hide most of omp's state, so `omp_signals` also reads the `dock` and `layer` regions of the agent's surface (`cx.session:surface` with `root`; never the `main` region, which holds the whole chat) and looks for omp's roles: `omp.ask.question` or `omp.plan.options` (it waits for you, while Tern still says `working`), `omp.working` with a `meter` child (retry countdown) or a `progress` child (compaction), `omp.errorBanner` (a pinned error) and `omp.hud.pill` (subagents or background jobs running while the agent is idle). These role names come from omp's TSP UI, not from an API, so an omp update that renames them turns those statuses back into Tern's plain ones. The rows are a Tern `ui.list`, because only a list keeps the cursor row in view; its id is `main.box.rows` because it sits in the box element keyed `box`. List item nodes drop child elements, so a row is styled spans only, all in the item's label: the jump number, the status mark, then the tree as box-drawing characters and the name. The jump number is plain `muted` text, and a typed first digit is `accent strong`. Every mark fills one 22 px slot so the names line up: a still glyph, or the empty slot of a row with no status, carries the `icon` token (Tern adds a margin after an icon span, which the sheet sets to 0), and the moving marks get margins that add up to 22 px. A still glyph uses the font `Symbols Nerd Font`: the `icon` token's font (Berkeley Mono, not installed) falls back to a font that draws the glyph past the right edge of its width, 2 px right of the slot's center. Without `Symbols Nerd Font`, the glyphs move off center again. An item and the list keep a `role` prop, which Tern writes as `data-role`, and that is the CSS hook of the line and of `goto.flat`. A status shows as a mark with no word. Plugin spans keep only Tern's own style tokens (custom tokens are dropped), so the CSS hooks onto Tern tokens: a moving mark is a no-break space with `num` plus a second token that picks it (`accent` working: Tern's step marker arc with `tnHdSpin`; `em` busy terminal: orbit dot with `sf-turn`; `ins` compacting: sliding bar with `sf-indet`; `del` three times, subagents or jobs: dots with `sf-dot`; `mark` retrying: widening rings in `--warn` with `tnRing`; `muted` idle: still hollow ring). A status that waits for you is a still Nerd Font glyph. A block region can carry `sf-still`, which stops animations, so each animation needs `!important`; the mark rules must not require `sf-still`, because a region does not always have it, and then the mark does not draw at all. The box and footer use the class names of Tern's command palette (`cmdk`, `ck-foot`, `kbd`), so Tern's own palette CSS styles them. If a Tern update renames those classes, tokens or keyframes, the picker loses that look. The `palette` sheet in `window.luau` fixes the floating pane to the window at the palette's spot (`12vh` from the top, centered with `50vw`), so an open file tree does not shift it. Its height of 511 px fits 20 rows of 22 px, the 13 px line, the list padding (12 px at the top, to match the space under the footer text, and 6 px at the bottom) and the 40 px footer, which must not shrink (`flex: none`); change it with the row height. A list with no line (no Waiting on you rows, or a search) has the role `goto.flat` and takes the line's 13 px as bottom padding, outside the scrolling area, so no part of a 21st row shows. It matches the pane by its accessible name (`aria-label` that starts with `Go to,`), because Tern's CSS engine has no `:has()`. The pane's shadow stops at the pane area, so while a picker is open the `veil` sheet darkens the rest of the window like the palette's veil: an inset shadow on `body` for the window background, and `filter: brightness(0.45)` on the tab bar items and the file tree. Keep the terminal grid of the pane in the page (the sheet only makes it invisible): it holds the input that sends typed keys to the block. `window_start` does not run after `tern plugin reload`, so a timer that starts when `window.luau` loads closes picker panes left from before the reload. `GLOSSARY.md` names the terms, and `docs/adr/0001-goto-picker-as-floating-block.md` gives the reason for the float.

## vstack

### Issue tracker

Issues live in the GitHub Issues of `daandden/tern-plugins`, and the skills use the `gh` CLI. See `docs/vstack/issue-tracker.md`.

### Triage labels

The repo uses the five default triage labels, and each label is the same as its role name: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human` and `wontfix`. See `docs/vstack/triage-labels.md`.

### Domain docs

The repo is single-context: one `GLOSSARY.md` at the repo root and the ADRs in `docs/adr/`. See `docs/vstack/domain.md`.
