# Tern plugins

This repo holds custom Tern plugins. Each top-level folder other than `bin/` and `docs/` is one plugin, with a `plugin.toml` manifest and a `window.luau` script. The folder name is the `id` in `plugin.toml`. `bin/` holds shell commands that work with the plugins.

## Loading

Tern loads each plugin from its folder in this repo. `tern plugin link <folder>` wrote a `<id>.path` file into the plugins directory (`tern plugin dir`, `~/.config/tern/plugins`), and that file names the folder. An edit here is the live plugin after a reload.

After each change:

1. Run `tern plugin reload`. It exits 1 when a plugin fails to load.
2. Run `tern plugin list` and make sure that each plugin shows `ready`.

To add a plugin, create `<id>/plugin.toml` and `<id>/window.luau`, then run `tern plugin link` once with the absolute path of the folder.

## Luau API

`tern plugin types <folder>` writes `<folder>/tern.d.luau`, the type definitions for luau-lsp. Read it for the API that the plugins use (`tern.command`, `tern.css`, `tern.route`, `cx.layout`, `cx.session`). The file comes from the installed Tern version, so `.gitignore` keeps it out of the repo. The SDK and its example plugins are at https://github.com/stencil-hq/tern-sdk.

## Conventions

Indent Luau with tabs. Each `window.luau` starts with a comment that says what the plugin does, and each function or command has a comment above it that says what it does. In zellij-keys, that comment names the Zellij action that the command copies.

## Plugin notes

zellij-keys: `~/.config/tern/settings.json` binds its commands as `plugin.zellij-keys.<command id>`. If you rename a command id, change its keybind in `settings.json` too. A running Tern keeps its settings in memory, does not read an edit of the file, and writes the whole file again at each change of a preference (zellij-keys changes `reduce_motion`). So a hand edit of the file while Tern runs is lost. Bind keys with Tern's Keyboard settings, or with `cx.settings:bind` from a plugin, which applies the key at once and saves it. The float commands use absolute paths in `/opt/homebrew/bin`, because Tern runs them through the login shell and that `PATH` does not include `/opt/homebrew/bin`.

zellij-keys floats: the floating panes of a tab are shown or hidden together, as in Zellij. The `focus` handler hides the shown floats of a tab with Tern's `pip_stash_all` when focus goes to a tiled pane of that tab from a pane of the same tab (a click, a key or an open). A focus that comes from another tab or session hides nothing, also when it lands on a tiled pane of a tab whose floats are shown. `focus_tab` keeps the tab of the last focus for that test. Alt+F from a tiled pane shows the floats and focuses the last used floating pane of the tab. A new float (`open_float`, `toggle_float`) shows the hidden floats first. `floats_shown` reads the state live: `cx.session:view(pane)` is nil only for a stashed float. Tern 0.9.5's `pip_stash_all` does not look at the floats of the active tab: it does the opposite of its last call anywhere in the window, so after a hide in another tab, or with one float shown by a focus, it shows when it should hide. So `stash_all` runs it, reads the state again, and runs it a second time when the floats are not as wanted. An override of `pip_stash_all` does the same for Tern's own key and palette entry. A call from `cx:command` skips the override. `tern.kv` keeps the last used floating pane of each tab under `last_float`, because a reload of any plugin resets every plugin's Lua state.

zellij-keys close: when the focused float closes and other floats of the tab are shown, `pane_closed` focuses the last used float of the tab, else the float before it in open order, else the one after it. `pane_closed` comes before the `focus` event of Tern's own move to the tiled pane, and the `focus` handler skips an event whose pane no longer has focus. The Go to picker counts as a focused float there, so Esc in a picker that a float opened goes back to that float. goto closes the picker before it focuses the target of a jump, and Tern first moves focus to the tiled pane under the picker. So a jump to that tiled pane gives the same events as Esc and also goes back to the float. Only a jump to another pane hides the floats. The picker is a `goto.picker` block, and `is_picker` leaves it out of the floating panes.

zellij-keys cascade: the `float-size` sheet draws each shown floating pane at half the tab (`.tn-stage`) in width and in height. The first float is centered, and each later one sits 16 px to the right and 32 px lower, in open order. After 8 places, the cascade starts at the top again and keeps going right, for 16 places. The sheet depends on Tern's class names: each float is a `section.tn-pane.pip` child of `.tn-stage` in open order, whatever its corner, a stashed float has `off`, a float that Tern does not draw has `off` and `pip-hidden`, the focused float has `pip-focus`, the floats behind it have `pip-glance` and `pip-peek` with a tilt transform, and `.tn-pip-chip` is the "Show all" chip. The stage also keeps the panes of each other tab that you looked at, with `off`. If a Tern update renames them, the cascade stops working. `:nth-child(k of .pip:not([aria-label^="Go to,"]):not(.off))` counts the drawn floats of the tab you look at without the Go to picker, so the picker keeps the box of goto's `palette` sheet and does not move the cascade. Tern writes the position, size and transform of a float inline, so each rule needs `!important`. Tern's engine ignores `inline-size`, so the rules use `width` and `height`. Tern paints the focused float on top with no `z-index`. The rules replace Tern's inline position, so the mouse cannot drag or resize a shown float. Issue #3 (https://github.com/daandden/tern-plugins/issues/3) waits for Tern to make that possible.

zellij-keys moves: Ctrl+G M and Ctrl+G R move and resize the focused float by a tenth of the tab, and Ctrl+G R +, Ctrl+G R -, Alt + and Alt - grow or shrink it on all sides, half a step on each side. A float that you moved or resized keeps its own spot until it closes or docks: through hide and show, a tab switch and a plugin reload. `tern.kv` keeps the spots under `float_spots`, by pane id, as parts of the tab (`x`, `y`, `w`, `h`), so a spot scales with the tab. `settle` keeps the float inside the tab and at least a fifth of it. An edge that ends within 5% of a tab edge snaps to `EDGE_GAP` (10 px) from that edge when the change moved it toward that tab edge, or when it was snapped and did not move away. So a shrink of a float that fills the tab lets go of the edges, and a move to the side leaves the top and bottom as they were. The resize commands clamp the size before they move the float, so at a fifth of the tab or the full tab a grow or shrink changes nothing, and Ctrl+G R with L or J stops at the tab edge with the top-left corner in place. The flags `l`, `r`, `t` and `b` mark the snapped edges, and the rule of a snapped edge uses px, so the gap stays 10 px at each tab size. When the one snapped edge of an axis lets go, the float keeps its 10 px shift from that edge as `dx` or `dy` (px, drawn as `calc(x% ± 10px)`) until an edge snaps again, so it does not jump; when both edges let go, there is no shift. `render_spots` writes the `float-spots` sheet: one rule per moved float of the tab you look at, with the same `:nth-child` count as the cascade and one more `:root`. The count leaves out the floats that Tern does not draw, so `drawn_floats` numbers the floats the same way: in each corner stack (the Go to picker included), only the 4 newest count. It runs on each focus, close and change, after `place_floats`, because the count changes with the tab, the corners and each float that opens or closes. A moved float keeps its place in the count, so the cascade place it left stays empty. A plugin cannot read the size of the tab, so the first move starts from the cascade place with its px offsets turned into parts of a 1260 by 710 tab (`TAB_GUESS`). Overrides of `move_pane:*` and `equalize` handle a float and return false for a tiled pane, so Tern's own action runs. Tern's `resize_split:*` is a key action that a plugin cannot override, so `settings.json` binds Ctrl+G R with H, J, K, L and the arrows to the `resize_*` commands, which run `resize_split:*` through `cx:action` for a tiled pane. Tern spells the keys as `ctrl+g>r>shift+=` (+), `ctrl+g>r>-`, `alt+shift+=` (Alt +), `alt+=` and `alt+-`.

zellij-keys app floats: F2, F3 and F4 (`float_yazi`, `float_lazygit`, `float_btop`, made by `float_command`) open their float with an own spot (`APP_SPOT`): centered, 80% of the tab in width and in height, in place of the half-tab cascade place. `open_float` writes the spot to `float_spots` before it focuses the pane, so the float acts as a moved one from its first frame: a move or resize starts there, and `equalize` puts it back at its cascade place. Two app floats in one tab sit at the same spot, with the focused one on top.

zellij-keys corners: Tern draws at most 4 floats in one corner stack (the floats of one tiled pane in one corner), and it gives the oldest floats of a fuller stack `off` and `pip-hidden`, also the focused one. Tern draws the whole stack only while the pointer is over it (a fanned deck, `pip fan` in `tern ctl`), and only one stack at a time: a fan of another stack folds the first one again. No action in Tern's action list fans a stack, so a plugin cannot keep one fanned. So `place_floats` puts the floats of each tiled pane in the corners `br`, `bl`, `tr` and `tl`, oldest first, with room for 3, 4, 4 and 4. `br` comes first, so up to 3 floats still hide to the right, and it keeps one place for the Go to picker, which goto opens there. So Tern draws 15 floats per tiled pane. With more, `br` takes the extra ones, and Tern draws 16, or 15 while the picker is open, and hides the oldest ones of `br`. A focused float never goes to a hidden place. `note_float_focus` calls `place_floats`, so each float focus places the floats again. The cascade rules set the position of a shown float, so its corner does not show.

zellij-keys motion: Tern animates floats outside CSS, so a command or handler that changes a float first calls `quiet_float_motion`, which sets `reduce_motion` to `on` for 400 ms. The user's value waits in `tern.kv` under `reduce_motion_before_float`, and `window_start` restores it if Tern stopped in between. Floats that the mouse focuses or unfocuses still animate. While `reduce_motion` is `on` and the window gets no input, `tern.timer` and `tern.sleep` do not fire, so the value stayed `on` until the next key. The 400 ms wait is a `/bin/sleep 0.4` process through `tern.process.run`, whose callback comes on time, and only the wait of the last call restores the value.

Agent tab: Alt+Shift+T runs Tern's own `new_agent_block`, and Tern's setting `agent_placement` is `new_tab`, so the agent opens in a new tab, in the folder of the focused pane. Every New agent block opens a tab, also from the palette.

zellij-keys worktree tab: Ctrl+Shift+T (`worktree_agent_tab`) adds a worktree of the focused pane's repo at its default branch and opens a new tab that runs omp there. The main checkout (the first `worktree` line of `git worktree list --porcelain`) may be on any branch and keeps it. The command stops with an error toast when that checkout has staged, unstaged or untracked changes (`git status --porcelain`). The default branch is the one `origin/HEAD` names, else the one of `main` and `master` that exists. With an `origin` remote, the command fetches that branch (30 s, `GIT_TERMINAL_PROMPT=0`) and compares the local branch with `origin/<branch>` through `rev-list --left-right --count`: ahead or diverged stops with a toast, so no unpushed default-branch commit is left behind, and the new worktree starts at `origin/<branch>`. A fetch that fails or times out shows an info toast and then uses the `origin/<branch>` that git already has, so a known unpushed commit still stops the command. When the local branch or `origin/<branch>` is missing, nothing is compared, and the worktree starts at `origin/<branch>` if it exists, else at the local branch. `omp worktree add` makes the worktree on a new `wt/<time>` branch in `<dir>/wt-<time>-<commit>`, where the dir is `OMP_WORKTREE_DIR`, else omp's `worktree.base`, else `~/.omp/wt`, and it clones the main checkout's ignored files when `worktree.clone` is on. omp's `/wt` is not used: it branches from the HEAD of its folder and copies that folder's changes. `cx.agents:start` rejects a blank prompt, and a `new_tab` in Agent mode opens in the folder of the focused pane, so `cx.layout:new_tab` runs omp as the tab's command, and Tern lists that pane as an agent. While a press runs its steps, `worktree_busy` makes a second press do nothing. Git and omp run from `/opt/homebrew/bin`, because Tern's `PATH` does not include it.

zellij-keys worktree settings: both `omp config get worktree.base` and `omp worktree add` run with the main checkout as their process cwd, so its `.omp/config.yml` applies. These worktrees are created before their omp session starts, so they are not owned by that session's `worktree.onExit` cleanup. Keep them until the user removes them explicitly.

zellij-keys fetch deadline: `/opt/homebrew/bin/gtimeout` (GNU coreutils) wraps the fetch and terminates its process group after 30 seconds, with `--kill-after=1s` for a process that ignores TERM. Tern's own `tern.process.run` timeout kills only the parent; a surviving SSH transport can keep its output pipes open and delay the callback past the deadline. The group deadline lets the command continue with the cached origin branch without waiting for the transport.

`keybinds.html` is the guide to every key that `~/.config/tern/settings.json` binds, grouped by zellij mode. When you add, remove or change a keybind or a zellij-keys command, change its row in the guide and the key count at the top.

reader-terminal-text: the plugin is CSS only, through `tern.css`. Its selectors use the class names and `data-role` values of Tern's Reader chat style (`.sf-chat-reader`, `omp.assistant`, `omp.editor`). If a Tern update changes these names, the rules stop working. The `:root` and `:root:root` prefixes give each rule a higher specificity than the Reader rule it replaces.

reader-terminal-text weight: Tern's Font weight setting (`font_weight`) sets `--tv-weight`, which only the terminal grid uses. Reader's `font` shorthands set message text back to 400, so the plugin gives that text `var(--tv-weight, 400)`, and its strong text and headings `bolder` (700 from 400, 900 from 600 or 700). Tern's CSS engine does not apply `min(900, calc(var(--tv-weight) + 300))` in `font-weight`, so bold cannot follow the grid's +300 exactly. Single-line chrome (tool titles, chips, status) keeps Reader's own weights.

html-links: every local HTML file that Tern would open as source opens as the rendered page. `tern.route.open` handles HTML files from the Files pane, the palette, `tern open`, `bin/open`, macOS open that names Tern (`open -a Tern`) and clicked plain paths. A clicked `file://` link is Tern's own: Tern 0.7.3 and later render a local HTML link beside its opener, also from a float, so the link route returns nil for every `file://` URL. Tern opens a `file://` link with a query or a fragment (`page.html?x=1#top`) as a file block named `page.html?x=1`; that is the accepted cost. When the rule for HTML files changes, change `is_html` here and in nvim-files. A page docks beside its opener pane. When that pane is a float (Yazi runs as one), `tiled_pane` finds the tiled pane under it in `cx.session:layout(tab).floats`, because a page docked beside a float stays a float. nvim-files keeps the same `tiled_pane`.

html-links web links: the link route returns nil for a URL to this machine (`localhost`, `*.localhost`, `127.x.x.x`, `::1`, `0.0.0.0`, or the local host name from `cx.hosts:list()`, also with `.local`), so Tern opens it. Every other web URL goes to `/usr/bin/open -a "Microsoft Edge"`. A link that you click inside a Tern page does not go through the route, so it stays in that page.

Default browser: Microsoft Edge is the macOS default app for `http`, `https` and HTML files. macOS keeps the three together: when Tern becomes the app for HTML files, it also becomes the default browser. So a URL or an HTML file that another app opens (Finder, Slack, `/usr/bin/open`) goes to Edge, and only opens that go through Tern reach the plugin routes.

html-links Cmd+R: `reload_page` reloads the focused browser pane, or from another pane the `file://` pages in its tab. Tern drops a plugin default key that a preset binds, and the preset binds `cmd+r` to SQLite actions. So `settings.json` binds `cmd+r` to a list: the four SQLite actions first, then `plugin.html-links.reload_page`. In a SQLite block, the SQLite action runs. If a Tern update changes the preset for `cmd+r`, change the list too.

nvim-files: local text files open in `/opt/homebrew/bin/nvim` in a terminal pane, because Tern's code view has no line height setting (https://github.com/stencil-hq/tern-sdk/issues/20). Markdown, notebooks, images, PDFs, databases, binary files and files over 4 MiB stay in Tern. Tern 0.9.5 resolves a symlink before it calls a route, so a symlink to a text file opens its target in Neovim. The plugin needs both routes. `tern.route.open` covers the Files pane, the palette, `tern open`, `bin/open` and clicked plain paths. `tern.route.link` covers clicked `file://` URLs: a link route that answers `{ path = ... }` makes Tern open its own file block without calling `route.open`. html-links' link route returns nil for every `file://` URL. A `file://` URL that does not go to Neovim gets `{ path = ... }` here and opens in Tern's file block. The plugin keeps the ids of its Neovim panes in `tern.kv` under `panes`, because a reload of any plugin resets every plugin's Lua state. A second file in the same tab goes to that pane as a typed `:drop` command (`cx:run`, not `cx.session:run`). A new Neovim pane from a float opener splits the tiled pane under the float (`tiled_pane`). Both routes return nil for every HTML file, so html-links or Tern handles it. If the HTML rule of html-links changes, change it here too. When the issue is fixed, remove the plugin.

bin/open: `~/.local/bin/open` is a symlink to `bin/open`, and `~/.local/bin` comes before `/usr/bin` in `PATH`. In a Tern pane (`TERN_PANE` is set), `open FILE...` with only local files runs `tern open` for each file, so the file opens beside that pane in its tab, also when you look at another tab. macOS open names no pane, so Tern opened such a file beside the focused pane. Every other call goes to `/usr/bin/open`. Tern does not give the pane of `tern open` to a plugin route, so the script writes the real path of the file to `~/.cache/tern/open-owners/<pane>.<pid>` first. html-links and nvim-files read the pane from that file in `take_opener` and remove the file. When two panes open the same path at once, `take_opener` takes the file of the focused pane, because `tern open` focuses the pane that runs it before the route runs. `tern open` exits 1 with "cannot open in a file block" when a plugin opened the file, so the script treats a removed handoff file as success and hides that message. `tern open` also shows the pane's tab, so the window moves to the tab of the pane that ran `open`. Both plugins keep the same `take_opener`. If you change it, change both.

Yazi: `~/.config/yazi/yazi.toml` (outside this repo) sends `*.{html,htm}` to the openers `open` and `edit`. Enter runs Yazi's `open` opener (`open %s`). The login shell is fish, and fish finds `bin/open` there, so the rendered page opens beside the tiled pane under the Yazi float. The "open with" menu (`O`) also offers `$EDITOR`. Without the rule, Yazi's preset sends `text/html` to the editor. In zsh and bash login shells, `/usr/bin` comes before `~/.local/bin`, so those shells miss `bin/open`.

goto: the window half lists sessions, tabs and tiled panes and passes them as JSON in the launch argument of the `goto.picker` block (host half). A tab with one pane is one row with that pane's status; only a split tab gets pane rows under it. A row is marked `agent` when its pane is in `cx.agents:list()` (a split tab when one of its panes is), and a split tab with exactly one agent pane names that pane's row in `solo`. After the tree rows, `collect` adds the Waiting on you rows (`group = true`): a copy of each row whose status is in `ATTENTION` (needs input, error, alert, done, idle), except the row you are in, by status and then last seen (see goto last seen). The picker has one mode: a typed letter or space goes into the search at once, a digit is a jump number (so a search holds no digits), only Up/Down move, and Esc clears the first digit, then the search, then closes. The actions sit behind the prefix `ctrl+;` (`state.prefix`): then `a` switches agents only and all panes, `i` shows or hides idle agents in Waiting on you, and every other key only ends the prefix. Tern's keymap does not bind `ctrl+;`, and the block gets it as `ctrl` with the name `;`; if `settings.json` ever binds `ctrl+;`, the prefix stops working. The host half filters the rows: it opens with agents only (`in_view`: every session row, the tabs and panes marked `agent`, and a `solo` tab as one row that shows and goes to its agent pane through `target`). `in_view` also hides the idle Waiting on you rows until `i` shows them. After each filter or search, `number_rows` numbers the shown rows. A session row that shows one tab row under it shares its number with that tab (`merged`), also when the filter or the search hides its other tabs, and the number goes where the tab goes (`destination`). That tab row shows an empty number slot, and Up/Down (`step`) skips it. A cursor that lands on such a row goes to its session row: in `place_cursor`, and in `action_key` when `a` hides the other tabs of the session. The pane rows of a split tab and the Waiting on you rows keep their own numbers, and the choice of one or two digits counts numbers, not rows. Tern has no plugin settings: `plugin.toml` rejects unknown keys, `cx.settings` knows only Tern's own preferences, and Tern drops an unknown key from `settings.json` when it writes the file. So `i` stores its choice in `tern.kv` under `waiting_idle` (default hidden), and each picker reads it in `init`. It shows the Waiting on you rows first, named session / tab / pane, then a thin line (an extra list item with the role `goto.sep`, outside the rows, so the cursor, jump numbers and clicks skip it), then the tree. It hides the group during a search, and `place_cursor` starts the cursor on the first group row, else on your pane's row, its `solo` tab row, or your session's row; `set_query` puts it there again when the search becomes empty. The footer shows the search and a text cursor on the left and is empty there without one; its keys are `↑ ↓ move`, `↵ go` and `⌃; actions`, and while the prefix waits, the two actions and `esc cancel`. The block reports the row you pick as a `goto:session/<id>`, `goto:tab/<id>`, `goto:pane/<id>` or `goto:close` link, and the window's `tern.route.link` makes the move. Pane status starts from `cx.agents:list()`: Tern lists omp panes there as agents (state `working`, `waiting_input`, `idle` or `exited`) even though they run in a terminal, and `cx.session:panes()` gives `busy` and `alert` for plain terminals. Tern's four states hide most of omp's state, so `omp_signals` also reads the `dock` and `layer` regions of the agent's surface (`cx.session:surface` with `root`; never the `main` region, which holds the whole chat) and looks for omp's roles: `omp.ask.question` or `omp.plan.options` (it waits for you, while Tern still says `working`), `omp.working` with a `meter` child (retry countdown) or a `progress` child (compaction), `omp.errorBanner` (a pinned error) and `omp.hud.pill` (subagents or background jobs running while the agent is idle). These role names come from omp's TSP UI, not from an API, so an omp update that renames them turns those statuses back into Tern's plain ones. The rows are a Tern `ui.list`, because only a list keeps the cursor row in view; its id is `main.box.rows` because it sits in the box element keyed `box`. List item nodes drop child elements, so a row is styled spans only, all in the item's label: the jump number, the status mark, then the tree as box-drawing characters and the name. The jump number is plain `muted` text, and a typed first digit is `accent strong`. Every mark fills one 22 px slot so the names line up: a still glyph, or the empty slot of a row with no status, carries the `icon` token (Tern adds a margin after an icon span, which the sheet sets to 0), and the moving marks get margins that add up to 22 px. A still glyph uses the font `Symbols Nerd Font`: the `icon` token's font (Berkeley Mono, not installed) falls back to a font that draws the glyph past the right edge of its width, 2 px right of the slot's center. Without `Symbols Nerd Font`, the glyphs move off center again. An item and the list keep a `role` prop, which Tern writes as `data-role`, and that is the CSS hook of the line and of `goto.flat`. A status shows as a mark with no word. Plugin spans keep only Tern's own style tokens (custom tokens are dropped), so the CSS hooks onto Tern tokens: a moving mark is a no-break space with `num` plus a second token that picks it (`accent` working: Tern's step marker arc with `tnHdSpin`; `em` busy terminal: orbit dot with `sf-turn`; `ins` compacting: sliding bar with `sf-indet`; `del` three times, subagents or jobs: dots with `sf-dot`; `mark` retrying: widening rings in `--warn` with `tnRing`; `muted` idle: still hollow ring). A status that waits for you is a still Nerd Font glyph. A block region can carry `sf-still`, which stops animations, so each animation needs `!important`; the mark rules must not require `sf-still`, because a region does not always have it, and then the mark does not draw at all. The box and footer use the class names of Tern's command palette (`cmdk`, `ck-foot`, `kbd`), so Tern's own palette CSS styles them. If a Tern update renames those classes, tokens or keyframes, the picker loses that look. The `palette` sheet in `window.luau` fixes the floating pane to the window at the palette's spot (`12vh` from the top, centered with `50vw`), so an open file tree does not shift it. Its height of 511 px fits 20 rows of 22 px, the 13 px line, the list padding (12 px at the top, to match the space under the footer text, and 6 px at the bottom) and the 40 px footer, which must not shrink (`flex: none`); change it with the row height. A list with no line (no Waiting on you rows, or a search) has the role `goto.flat` and takes the line's 13 px as bottom padding, outside the scrolling area, so no part of a 21st row shows. It matches the pane by its accessible name (`aria-label` that starts with `Go to,`), because Tern's CSS engine has no `:has()`. The pane's shadow stops at the pane area, so while a picker is open the `veil` sheet darkens the rest of the window like the palette's veil: an inset shadow on `body` for the window background, and `filter: brightness(0.45)` on the tab bar items and the file tree. Keep the terminal grid of the pane in the page (the sheet only makes it invisible): it holds the input that sends typed keys to the block. `window_start` does not run after `tern plugin reload`, so a timer that starts when `window.luau` loads closes picker panes left from before the reload. `GLOSSARY.md` names the terms, and `docs/adr/0001-goto-picker-as-floating-block.md` gives the reason for the float.

goto last seen: `collect` puts the tabs of each session and the panes of each split tab last seen first (`last_seen_first`); sessions keep Tern's order. Tern has no time of last focus, so the `focus` handler counts each focus in `tern.kv` under `seen`: a counter `n`, and the count of the last focus by pane id (`panes`) and by tab id (`tabs`). A count, not a time, keeps the order of two focuses within one second. Every focus counts at once, also one that only passes through a tab. A floating pane's focus counts for its tab only, and the picker's own focus does not count. `open_picker` counts the focused pane first, so your own pane leads its tab, and your own tab leads the tabs of its status. Panes and tabs with no count come after the counted ones, in Tern's order. `pane_closed` and `tab_closed` drop the closed ids. The Waiting on you rows keep their status order, and inside one status they come last seen first by the count of their pane (`pane_of`), also the row of a tab with one pane, so a float's focus does not move that row. Rows whose pane has no count follow, in tree order. `seen_before` is the one comparison for both orders.

goto tab order: the host half (`tree_order` in `host.luau`) puts the tabs of each session by their tab status, in the order of `TAB_ORDER` (input, error, alert, done, idle, retrying, compacting, working, background, running, exited, then a quiet tab), and tabs of the same status in `collect`'s last seen order. A tab with one pane has that pane's status. A split tab takes the first status in `TAB_ORDER` among its panes that the view shows: agent panes with agents only, every tiled pane with all panes. So `ctrl+;` then `a` can change the tab order. Floating panes give no status. A search keeps the same order. Sessions, the panes of a split tab and the Waiting on you rows keep their own order.

goto zoom: Tern's interface size zooms the block region by `--tn-zoom` and sets `--sf-fs` to the terminal size divided by the zoom, and Tern's own palette (`.tn-cmdk`) zooms again by `--tn-zoom`. So the `palette` sheet scales the pane's left edge, width, height (511 px) and corner by `var(--tn-zoom, 1)`, and gives the box `zoom: 1` and the font size `var(--tv-fs)`, so the picker sits where the palette sits at each interface size. Inside a zoomed element, px scales with the zoom and vh does not, and Tern's engine ignores `max-height: 100%` and flex-shrink on the box, so its `max-height` divides the px part by the zoom.

goto motion: Tern animates the picker's float as it grows into view, outside CSS, so `open_picker` first calls `quiet_motion`, which sets `reduce_motion` to `on` for 400 ms, the same way as zellij-keys' `quiet_float_motion`. The user's value waits in goto's `tern.kv` under `reduce_motion_before_open`, and `window_start` restores it if Tern stopped in between. While `reduce_motion` is `on`, a `tern.timer` can fire only when the value goes back, so both waits are `/bin/sleep` processes: the 400 ms one and the 60 ms refocus of `open_picker`. A refocus that waits longer leaves the picker unsettled, so a click elsewhere does not close it. When zellij-keys already holds `reduce_motion` at `on`, `quiet_motion` saves nothing and zellij-keys restores the value. The box carries Tern's palette class `cmdk`, whose CSS animation `cmdkIn` fades and slides the palette in. `reduce_motion` makes it last 0 s, and Tern plays it again when the value goes back after the 400 ms, so the `palette` sheet gives `.goto-box` `animation: none`.

goto finished: Tern sends `agent_finished` when an agent's turn ends, for every agent kind. `tern.kv` keeps under `finished` the result of each agent pane's last turn that you have not seen: `done`, or `error` for a `failed` turn. A turn that ends while its pane has focus stores nothing, because you saw it. `exited` and `closed` clear the entry, and so do a focus of the pane and its close. `pane_status` shows a stored `error` as `error` and a stored `done` as `done`, after the live states (input, retrying, compacting, working). An exited agent keeps its `exited` mark and stays out of Waiting on you. Tern also raises its own finished or failed inbox alert after each turn, which shows as `done` through `info.alert`. An Esc cancel in omp sends no event and leaves Tern's state `working`.
